# QA portal integrity and security corrections

Base revision: `ba7b7444a08b968b78c9b7581353757fabbd0993`.
Branch: `fix/qa-portal-integrity`.

## Implemented

- Replaced automatic/demo login with explicit authentication, durable hashed session tokens, cross-worker revocation, origin validation and fail-closed production configuration. Removed bundled sample database and stale Bun lockfile.
- Enforced role, author, team and department access on server endpoints. Admin has authorized read/report access but cannot bypass assessment or dispute restrictions through imports.
- Made scoring authoritative on the server, with complete integer item validation, immutable historical forms, Support/Sales budgets, fraud/critical zeroing, mistake-policy snapshots and partial-update recalculation.
- Added transaction-backed audit writes, assessment revisions, stale-edit rejection, duplicate-ticket confirmation, request idempotency, soft deletion and supervisor restoration.
- Enforced dispute ownership/window, canonical states, criterion-specific correction, unique dispute targeting and controlled supervisor overrides.
- Unified monthly reports, dashboards and spreadsheet exports using Tehran/Jalali month boundaries and the Sales monthly fraud policy. Missing data remains empty rather than invented.
- Reworked CSV validation, previews and atomic imports, preserving original controller attribution and marking aggregate-only historical data explicitly.
- Added scoped record history, paginated assessment/dispute/audit views, user/team management, rubric editing, configurable result options and consistent API error handling.
- Removed misleading success states: forms close after successful server responses, asynchronous account changes cannot display another session's data, and JSON snapshots are clearly distinguished from database backups.
- Replaced the vulnerable spreadsheet library with ExcelJS and updated Express/Vite and relevant dependencies. Split large frontend screens into lazy-loaded chunks.
- Added isolated test/bootstrap/migration scripts, SQL Server column/index corrections, CI jobs and deployment/backup/rollback instructions.

## Remaining verification and product decisions

Full browser execution was unavailable because Chromium downloads failed in this environment. A live SQL Server was unavailable; schema checks do not replace the SQL Server CI smoke job. No production database, corporate SSO, real mobile device, VPN, load test or backup restore was accessed or verified. CI configuration is supplied; remote CI success is not claimed.

Real corporate SSO, notifications and calibration remain deferred. Vite/Express and the split assessment workspace remain, rather than a Next.js migration or a four-step wizard. Historical organizational transfers need organization-specific validation where old roster history is missing. These limitations are documented in README.md; this change is not a claim of exhaustive or production-environment testing.

## Apply safely

Use the source in this branch/archive and follow **Existing installation: non-destructive upgrade** in README.md. Back up the existing database, review an additive schema migration, run the integrity migration and validate staging before deployment. Do not seed or replace an existing database with demo data. New production installations require real configuration and administrator bootstrap.
